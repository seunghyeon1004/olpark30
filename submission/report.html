올팍 30분

공연이 끝난 뒤 출차 대기 시간을 공원 산책으로 바꾸는 서비스, 공공데이터 활용사례 설명서
한국체육산업개발(주) 공공데이터 활용 경진대회. 작성자 백승현(개인). 개방 데이터 9종을 사용하고(파일 7종, 실시간 API 1종, 공연정보 API 1종) 2종은 연계 예정입니다.

1. 배경과 문제

대형 공연이 끝나면 올림픽공원 주차장 출차가 한꺼번에 몰립니다. 주최 측이 예시로 든 '혼잡 예측·분산 안내'는 혼잡을 피하게 하는 접근입니다. 올팍 30분은 한 걸음 더 나아가 혼잡을 쓸모 있게 만듭니다. 출차 대기 시간을 정확히 추정해 알려 주고, 그 시간만큼 바로 옆 공원을 걷는 코스를 구성합니다. 이용자는 차 안에서 기다리는 대신 걷고, 기관은 출차 피크가 분산되며 공원 체류가 늘어납니다.

실측으로 확인한 규모: 2025-12 관람객 2만 명대 콘서트(12-05, 12-06)에는 주차장에 3,000대 이상이 찼고, 몰림 구간의 초과 출차는 약 2,410대와 1,962대, 90%가 빠지기까지 100~105분이 걸렸습니다.

3. 서비스 화면 (모바일 우선)

이용 흐름

  • 입차 전: 공연 서지 규모, 구역별 혼잡 기록, 실시간 주차 대수를 보고 일정을 계획합니다.
  • 공연 후: 공연 규모(중소, 대규모)와 출차 줄이 몰리기 시작한 뒤 경과 분을 고르면 "지금 줄에 서면 최대 40분(대규모는 최대 약 103분), 20분 뒤면 최대 20분"처럼 대기 상한을 보여 줍니다.
  • 대기가 길면: 날짜(계절)·남는 시간에 맞춘 산책 코스를 제안하고, 몰림이 풀린 뒤 돌아오도록 안내합니다.

4-1c. 공연 종료와 출차 몰림 시작의 간격

공연정보 API(3037877)에는 2025-12 공연이 없습니다. 대신 같은 아티스트(god)의 과거 KSPO DOME 콘서트 기록 5건이 모두 공연 시간 150분이고, 가장 최근 2023·2024 시즌은 둘 다 금 20:00, 토 18:00, 일 17:00이어서 12-05(금)와 12-06(토)의 시작을 20:00과 18:00으로 보았습니다. 게이트 파일의 입차 피크가 두 날 모두 시작 약 75분 전(18:45, 16:45)이라 이 가정과 맞습니다. 종료는 22:30과 20:30이고, 비공연일 기준선 대비 초과 출차가 처음 연속 상승한 시각은 22:55와 20:55로, 종료 후 25분이었습니다(표본 2회, 시작 시각은 추정). 앱은 사용자가 공연 시작 시각을 넣으면 종료와 몰림 시작 시각을 이 규칙으로 보여 줍니다.

4-3. 검증 (하루 제외 교차검증)

용량 기반 큐 모델은 90% 해소 시점을 평균 14.2분 틀려 정확도가 낮았고, 단순 경험 평균 예측은 평균 오차 4.2분이라 후자를 채택했습니다. 표본이 중소 규모 5일이고 대규모는 2회뿐이라 정합성 점검 수준이며 강한 검증이 아닙니다. 중소 규모에서는 해소 시간이 30~45분으로 안정적이었지만, 2025-12 대규모(관람객 2만 명대)에서는 100~105분으로 크게 길었습니다.

4-4. 한계

  • 대기열 자체는 어느 파일에도 기록되어 있지 않아 정산 통과 시각 분포로 간접 추정합니다(상한).
  • 공연 시작 시각은 사용자가 입력해야 하며(API에 2025-12 공연 없음), 종료 후 25분 간격은 2회 표본입니다.
  • 대규모 표본은 2회(12-05, 12-06)이고, 게이트 파일은 10만 건 상한으로 12월 첫 주만 출차를 관측합니다.
  • 산책 코스는 잔디시설 개방기간만 공공데이터 근거이며 체류 시간은 가정값입니다(좌표·거리 데이터 없음).
